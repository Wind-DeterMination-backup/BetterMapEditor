# mindustry.maps.filters 层说明

## 这一层负责什么
这一层承载项目最底层、最具体的镜像滤镜实现。上层功能编排只负责“何时替换、何时拖拽、何时刷新”，真正“镜像轴在哪里”“怎样绘制轴线”“如何根据轴线求对称 tile”的算法都在这里。

## 本层文件

- `DraggableMirrorFilter.java`
  基于原版 `MirrorFilter` 的增强实现。

## DraggableMirrorFilter 的核心能力

- 新增 `axisX` 和 `axisY`
  用 0 到 1 的归一化坐标表示镜像轴经过地图上的哪个点，默认中心点 `(0.5, 0.5)`。
- 保留原版参数
  `fromMirror(...)` 会复制 `seed`、`angle`、`rotate`，保证旧镜像滤镜迁移后行为连续。
- 自定义 `apply(...)`
  把当前处理点和镜像轴关系算出来，只对轴一侧执行镜像取样，然后回填 `floor`、`block`、`overlay`、`packedData`。
- 自定义 `draw(...)`
  在预览图上画出高亮镜像轴和轴心点，让用户能直接看到拖拽目标。

## 数学与坐标实现

- `axisCoord`
  把归一化轴坐标映射到地图离散坐标系，使用 `size - 1` 保证边界点能落到最外侧格子。
- `mirror(...)`
  继承原版几何思路。若地图非正方形且角度不是 90 度倍数，或开启 `rotate`，则走翻转逻辑；否则按直线镜像公式求对称点。
- `left(...)`
  用叉积符号判断点在轴线哪一侧，决定是否需要镜像采样。
- `clipHalfLine(...)`
  把方向向量裁切到预览矩形边界，使绘制出来的是完整可见线段而不是无限长射线。

## 兼容性实现

- `tileSafe(...)`
  通过反射调用 `GenerateInput.tile(...)`，同时兼容 `int,int` 或 `float,float` 两种潜在签名。
- `resolveTileMethod()`
  首次调用时缓存方法对象，后续直接复用，减少反射开销。
- 失败保护
  若反射或镜像处理出错，只记一次错误日志，不让整个地图生成预览线程崩掉。

## UI 绘制实现

- `computePreviewRect(...)`
  根据编辑器地图尺寸与预览控件尺寸，计算实际地图内容在控件中的 letterbox 矩形。
- `draw(...)`
  先把轴心换算到局部坐标，再沿轴方向裁出两端点，最后用 `Pal.accent` 绘制高亮线和圆点。

## 与其他层级的关系

- 上游由 `bettermapeditor.features.DraggableMirrorAxisFeature` 创建、替换、拖拽和刷新。
- 本层不关心设置菜单、更新检查、发布流程。
- 它是整个项目最接近“原版地图滤镜核心逻辑”的一层，因此承担了最多的几何、反射和容错细节。
